# 🧩 เกมต่อจิ๊กซอว์ – แข่งความเร็ว (Turso)

โปรแกรมตัวอย่างสำหรับฝึกเขียนเว็บแอปที่ต่อฐานข้อมูลบนคลาวด์ หน้าเกมอยู่ที่ `public/index.html` และมี Backend ขนาดเล็กบน Netlify เก็บ Token ไว้ฝั่งเซิร์ฟเวอร์ ไม่ต้องติดตั้งอะไรเพิ่ม

## ความสามารถ
- แนบรูปเองได้ (โปรแกรมครอปเป็นสี่เหลี่ยมจัตุรัสให้อัตโนมัติ) หรือใช้รูปตั้งต้น
- เลือกจำนวนชิ้นได้ 9 / 16 / 25 / 36 / 49 / 64 ชิ้น
- จับเวลาและนับจำนวนครั้งที่ย้ายชิ้น
- มี 3 โหมด
  1. **เล่นคนเดียว**
  2. **2 คน ผลัดกันเล่น** บนเครื่องเดียว โดยทั้งสองคนได้ชิ้นที่สลับไว้เหมือนกัน แล้วเทียบเวลากัน
  3. **2 คน แข่งพร้อมกัน** บน 2 เครื่อง คนหนึ่งสร้างห้องแล้วได้รหัส 4 หลัก อีกคนกรอกรหัสเข้าห้อง ระหว่างเล่นจะเห็นความคืบหน้าของคู่แข่งแบบสด
- บันทึกผลลง Turso และดูตารางคะแนนได้ (กรองตามจำนวนชิ้นได้)
- ถ้าเชื่อมต่อฐานข้อมูลไม่ได้ จะบันทึกผลไว้ในเบราว์เซอร์แทน ส่วนโหมด 2 เครื่องต้องใช้ฐานข้อมูล

## โครงสร้างไฟล์
```
jigsaw/
├── netlify.toml              ตั้งค่า Netlify
├── netlify/functions/api.mjs Backend (ฝั่งเซิร์ฟเวอร์ ใช้ Token ที่นี่)
├── public/index.html         หน้าเกม (ไม่มี Token)
├── schema.sql
└── README.md
```
หลักการ: `เบราว์เซอร์ → /api (Netlify Function) → Turso`
เพื่อนได้แค่ลิงก์เกมก็เล่นได้ ไม่ต้องรู้ URL หรือ Token

## ขั้นตอนติดตั้ง (ทำผ่านเบราว์เซอร์ทั้งหมด)

### ขั้นที่ 1: ยกเลิก Token เก่า แล้วสร้างใหม่
ทำขั้นนี้ถ้าเคยส่ง Token ให้ใคร หรือเคยกรอกในเกมเวอร์ชันเก่า
1. ที่ turso.tech เปิดฐานข้อมูล แล้วหาเมนู **Invalidate Tokens** (หรือใช้คำสั่ง `turso db tokens invalidate <ชื่อฐานข้อมูล>`)
   - ⚠️ Token ของฐานข้อมูลอื่นใน group เดียวกันจะใช้ไม่ได้ด้วย ถ้ามีแอปอื่นใช้อยู่ ต้องออก Token ใหม่ให้แอปนั้น
2. สร้าง Token ใหม่แบบอ่านและเขียนได้ (Read & Write) และคัดลอก Database URL (`libsql://...turso.io`)
3. อย่าวาง Token ใหม่ในโค้ด ในแชต หรือใน GitHub ให้วางใน Netlify (ขั้นที่ 4) เท่านั้น

### ขั้นที่ 2: อัปโหลดไฟล์ขึ้น GitHub
1. แตกไฟล์ `jigsaw-netlify.zip`
2. เปิด repository `jigsaw` (ยังไม่มีให้สร้างใหม่) แล้วกดปุ่ม **.** เพื่อเปิด github.dev
3. ลบ `index.html` ตัวเก่าที่อยู่ชั้นนอกสุด
4. ลากของ**ข้างใน**โฟลเดอร์ `jigsaw` ทั้งหมด (`netlify`, `public`, `netlify.toml`, `schema.sql`, `README.md`) ไปวางในแถบ Explorer
5. ตรวจว่าตำแหน่งไฟล์ตรงกับผังด้านบน แล้ว **Commit & Push**

ถ้าเคยเปิด GitHub Pages ให้ปิดที่ Settings › Pages (Unpublish) เพราะเกมเวอร์ชันใหม่ใช้กับ GitHub Pages ไม่ได้

### ขั้นที่ 3: สร้างโปรเจกต์บน Netlify
1. เข้า https://app.netlify.com แล้วสมัครหรือล็อกอินด้วย GitHub
2. กด **Add new project › Import an existing project › GitHub** อนุญาตการเข้าถึง แล้วเลือก repo `jigsaw`
3. ไม่ต้องใส่ Build command (ค่าโฟลเดอร์อ่านจาก `netlify.toml`) แล้วกด Deploy

### ขั้นที่ 4: ใส่ Token ใน Netlify
ไปที่ **Project configuration › Environment variables** แล้วเพิ่มสองตัว (ชื่อต้องตรงทุกตัวอักษร)

| Key | Value |
|---|---|
| `TURSO_DATABASE_URL` | `libsql://...turso.io` |
| `TURSO_AUTH_TOKEN` | Token ใหม่จากขั้นที่ 1 |

- ที่ `TURSO_AUTH_TOKEN` ให้ติ๊ก **Contains secret values** และใส่ค่าในช่อง **Production**
- จากนั้นไปที่ **Deploys › Trigger deploy** เพื่อ deploy ใหม่ ค่าที่เพิ่มจึงจะมีผล

### ขั้นที่ 5: เปิดให้เพื่อนเข้าได้
บัญชีใหม่ของ Netlify มักตั้งโปรเจกต์เป็น **Private** (เห็นได้เฉพาะเจ้าของ)
ไปที่ **Project configuration › General › Visitor access › Project visibility** แล้วเลือก **Public** (ต้อง deploy สำเร็จอย่างน้อย 1 ครั้งก่อน)

### ขั้นที่ 6: ตรวจสอบ
- [ ] เปิดลิงก์ `https://ชื่อโปรเจกต์.netlify.app` แล้วจุดที่ปุ่ม "ฐานข้อมูล" เป็นสีเขียว (ถ้าไม่เขียว กดปุ่มเพื่ออ่านสาเหตุ)
- [ ] เปิดลิงก์ในหน้าต่างไม่ระบุตัวตนหรือมือถือที่ไม่ได้ล็อกอินได้
- [ ] เล่นคนเดียวจนจบ แล้วตารางคะแนนขึ้นว่า "ข้อมูลจาก Turso"
- [ ] แข่ง 2 เครื่องด้วยรหัสห้องได้

## ความปลอดภัย: ป้องกันอะไรได้บ้าง
**ป้องกันได้**
- Token ไม่ถูกส่งไปที่เบราว์เซอร์
- ผู้เล่นส่ง SQL เองไม่ได้ ทำได้เฉพาะคำสั่งของเกม และข้อมูลถูกตรวจฝั่งเซิร์ฟเวอร์
- แต่ละคนในห้องมีกุญแจของตัวเอง จึงแก้ข้อมูลของคู่แข่งผ่าน API ไม่ได้

**ยังป้องกันไม่ได้**
- เกมไม่มีระบบล็อกอิน ใครรู้ลิงก์ก็เล่น ดูตารางคะแนน และสร้างห้องได้
- เวลาและจำนวนครั้งมาจากเบราว์เซอร์ คนที่เขียนโค้ดเป็นยังปลอมคะแนนได้ (เซิร์ฟเวอร์กันได้แค่ค่าที่ผิดปกติ)
- รหัสห้องมี 4 หลัก คนอื่นอาจเดารหัสเพื่อเข้าห้องที่ยังรออยู่
- Rate limit แค่ช่วยชะลอการยิงคำขอรัว ๆ

## โครงสร้างโค้ด (ใน `<script>`)
| ส่วน | หน้าที่ |
|---|---|
| 1 ตัวช่วยทั่วไป | `fmt()` แปลงเวลา, `shuffle()` สุ่มลำดับชิ้น, `show()` สลับหน้าจอ |
| 2 เรียก Backend | `api(action, data)` เรียก Backend (คำสั่ง SQL อยู่ใน `api.mjs`) |
| 3 บันทึก/อ่านคะแนน | `saveResult()`, `loadBoard()` |
| 4 รูปภาพ | `loadImageFile()` อ่านไฟล์ → `cropToSquare()` ย่อเหลือ 500×500 |
| 5 ตัวเกม | `class Puzzle` เก็บ `order[ตำแหน่ง] = หมายเลขชิ้น` ต่อเสร็จเมื่อ `order[i] === i` |
| 6 เวลา | `timer`, `countdown()`, `poll()` |
| 7 โหมดการเล่น | `startSolo()`, `startTurn()`, `hostRoom()` / `joinRoom()` / `beginOnline()` |
| 8 ปุ่มต่าง ๆ | เชื่อมปุ่มบนหน้าจอเข้ากับฟังก์ชัน |

**หลักการของโหมด 2 เครื่อง:** ทั้งสองเครื่องไม่ได้คุยกันโดยตรง แต่ใช้ตาราง `rooms` เป็นตัวกลาง เครื่องแต่ละเครื่องเขียนความคืบหน้าของตัวเองลงไป แล้ว **poll** (อ่านซ้ำทุก 1.5 วินาที) เพื่อดูข้อมูลของอีกฝั่ง เวลาเริ่มเกมกำหนดด้วย `started_at` เพื่อให้นับถอยหลังพร้อมกัน

## ตัวอย่างงานให้นักเรียนพัฒนาต่อ
1. **พื้นฐาน:** เปลี่ยนสีธีม เพิ่มตัวเลือก 100 ชิ้น (10×10) หรือเพิ่มเสียงตอนต่อเสร็จ
2. **SQL:** ทำหน้า "สถิติของฉัน" แสดงจำนวนครั้งที่เล่น เวลาเฉลี่ย และสถิติดีที่สุด (มีตัวอย่างใน `schema.sql`)
3. **ตรรกะเกม:** เปลี่ยนจากคลิกสลับเป็นการลากวาง (Drag & Drop) หรือให้ชิ้นที่ถูกที่แล้วล็อกไว้
4. **ฐานข้อมูล:** เพิ่มตาราง `players` แล้วเชื่อมกับ `results` ด้วย `player_id` (Foreign Key)
5. **ความยุติธรรม:** ทำโหมดที่ให้ทุกคนในห้องใช้รูปและชุดสลับเดียวกัน (Daily Challenge)
6. **ท้าทาย:** ขยายห้องแข่งให้รองรับมากกว่า 2 คน
